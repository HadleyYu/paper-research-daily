# Candidate JSON contract

`prepare`, `pool`, and `publish` accept either an array of paper objects or an object containing `papers: [...]`. Preserve UTF-8 text. Search exports are discovery records, not publication-ready cards; the agent must verify and enrich them. [candidate.example.json](../examples/candidate.example.json) is deliberately synthetic and marked `example_only: true`; the publication helper rejects it.

## Bibliographic and reading fields

| Field | Type and meaning |
| --- | --- |
| `title` | Nonempty verified title |
| `authors` | Array of author-name strings; verified names required for publication |
| `doi` | DOI string or `null`; a DOI URL is normalized; never fabricate one |
| `arxiv_id` | arXiv ID or `null`; identity normalization removes the version suffix |
| `venue` | Human-readable venue, year, volume/pages, or preprint designation |
| `official_url` | Verified official entry URL, especially important if a PDF is unavailable |
| `version` | Actual version read/downloaded, e.g. accepted manuscript versus publisher PDF |
| `category` | `published`, `new_arxiv`, or user-enabled-source `new` |
| `publication_status` | For published candidates: `published` or `online_first`, supported by an official source |
| `evidence_level` | `fulltext` or `abstract`; must describe what the agent actually read |
| `one_sentence` | Brief positioning statement for the reader |
| `source_pdf` | Optional local PDF path; absolute, or relative to the configured library root |
| `download_status`, `download_reason` | Explain unavailable PDFs; at least one is required without a PDF, together with a DOI or official URL |

The helper verifies PDF readability, computes page count and SHA-256, copies the selected file into the dated folder, and writes its output filename. Do not manually invent a hash or pretend an HTML error page is a PDF. An unavailable download does not imply abstract-only reading if an official HTML full text was actually read; explain the evidence and source accurately.

Keep downloaded candidates under `.work/` after the initial scan, so new downloads are not mistaken for previously owned papers. `scan` should run before those downloads. Existing, unidentified PDFs require inspection; a filename alone is not sufficient paper identity.

## Source records

`sources` is an array of objects. Each should include `url`, `role`, and useful evidence such as `checked_at`, `title`, `note`, or source location. Use HTTP(S) URLs and verify that they substantiate the stated role. The helper checks structural eligibility, not whether a page actually proves a claim; that verification is the agent's responsibility.

| Purpose | Recognized role and additional requirements |
| --- | --- |
| Formal publication | `publication` or `official_publication`; `publication_status` must be `published` or `online_first` |
| arXiv-only discovery | `announcement`, `arxiv`, `discovery`, or `primary_publication` on `arxiv.org`, `export.arxiv.org`, or `rss.arxiv.org`; provide actual discovery/list evidence |
| Other new-work source | `announcement` or `primary_publication`; `discovery_source` must be enabled in the profile |
| Original abstract/full text | `abstract`, `fulltext`, `full_text`, `publication`, `official_publication`, `arxiv`, or `primary_publication` |

For new work, supply `discovery_source` and `first_announced_date` as `YYYY-MM-DD`. The latter is a verified first public announcement date, not an inferred submission date or an updated version date. Preserve exact timestamps and the source timezone in additional evidence fields when available. The helper checks the maximum date window; the agent must enforce and document the preferred hourly window and source-batch coverage.

## Card and score

Full-text records require all nine `sections` keys:

```text
abstract
problem
mechanism
novelty
evidence
limitations
relevance
microexperiment
reading
```

Use the structure in [reading-card](reading-card.md). Section values may be Markdown strings; structured lists/objects can also be rendered. `microexperiment` is the stable schema key for a proposed test or next step, including nonexperimental disciplines. The abstract must be a verified paraphrase with source attribution. Reading cards remain agent-authored evidence, not content generated by the storage helper.

`score` has exactly these six numeric keys, bounded by the confirmed profile's maxima:

```json
{
  "relevance": 30,
  "evidence": 21,
  "inspiration": 17,
  "novelty": 8,
  "representative": 4,
  "reproducibility": 3
}
```

The numbers above illustrate shape only, not a rating of a real work. Include `score_reason` and `selection_reason`; the helper computes the total. Array order determines final reading priority. If a published work fills a missing weekday new-paper slot, include a specific `fallback_reason` on each replacement.

Abstract-only records are disabled by default. When the user explicitly enables them, supply an accurate abstract and source and avoid unsupported full-text claims. They can remain unscored and visibly pending full-text verification; any supplied score must still meet the configured schema and thresholds. Do not exploit abstract-only settings to label an uncertain candidate a high-quality completed review.

## Pool and run fields

For `pool` or `prepare`, `status` may be `active`, `candidate`, `prepared`, `awaiting_verification`, `deprioritized`, `rejected`, or `archived`. Provide `candidate_reason` or `reason` describing that state. The helper preserves prior recommendation history and preexisting status; a pool update cannot set a paper to `preexisting` or `recommended`.

Optional `search_log` entries should record source/query/time/window, coverage, verification, download attempts, and limitations. Extra evidence fields such as original section/page references, first submission, raw metadata URL, or repository version are preserved. Keep them factual and free of credentials.

The engine derives identity from normalized DOI/arXiv IDs and hashes. `aliases` can record verified identity relationships when resolving versions. Do not force a match by adding an unverified alias. Similar normalized titles with overlapping authors trigger an identity-resolution error; inspect and resolve the relationship before retrying.

## Publication and validation boundaries

`prepare` and `pool` save candidate evidence without recommending it. `publish` accepts the selected array in priority order, checks eligibility and history, and commits the dated report plus registry through a recoverable local transaction. Identical same-date content returns `unchanged`; different content for an existing date is refused to prevent a silent rewrite.

Version 0.1 requires exactly the confirmed `daily_count` at publication. If too few qualified papers are available, retain partial reading with `prepare` and report the actual count and missing evidence to the user; do not fill slots with weak or fabricated candidates or claim completion. Pool limits and reassessment intervals require agent judgment; they are not automatic Python pruning jobs.

`validate` checks local files, PDF hashes/readability, recommendation history, counts, ranks, and local Markdown links. It does **not** fetch every remote link or authenticate scholarly claims. The agent must verify official pages, abstract correspondence, publication status, code identity, and important evidence separately. Scanned PDFs with little extractable text require visual reading or OCR review; a parsing warning is not by itself evidence that the file is invalid.
